# Ophidian: структура репозитория-волта

Дата: 2026-07-25

## Задача

Сейчас язык описан дважды: рукописными YAML в корне репозитория и заметками в
`obsidian-ophidian-vault/`. Копии уже разъехались. Нужна одна структура, в которой
понятно, где лежит правда, и которую можно вести из Obsidian без специальных знаний.

## Решения

1. **Источник правды — заметки волта.** Рукописных YAML не остаётся ни одного; весь
   YAML генерируется из заметок в `build/`.
2. **Корень репозитория = корень волта.** Один git-репозиторий, один волт, одна раскладка.
3. **Bases, не Dataview.** Bases встроен в Obsidian и настраивается мышкой; Dataview —
   плагин со своим языком запросов. Нужные выборки — «таблица плюс фильтр», это ровно
   область Bases.
4. **Существующие скрипты — легаси.** `transliteration.py`, `transpose-script.py`,
   `dictionary.html` написаны как эксперименты и будут переписаны. Их текущие форматы
   ввода-вывода **не являются ограничением** для схемы `build/`: схема проектируется
   удобной, а скрипты потом подгоняются под неё.

Инвариант, ради которого всё затевается: **`Language/` пишет только человек через
Obsidian, `build/` пишет только скрипт.** Ни один файл не правится с двух сторон.

`docs/`, `tools/`, `tests/` и `build/` добавляются в Obsidian → Settings → Files and
links → Excluded files, чтобы не мелькали в поиске.

## Схема заметок

Frontmatter обязателен для типов `lexeme`, `root`, `affix`, `noun_class`, `verb_class`.
Заметки в `Grammar/` и `Phonology/` — проза без frontmatter, схема на них не
распространяется.

Правила для всех типов:

- пустое значение записывается как пустое (не `""` и не `[]`);
- ссылка на другую заметку — `"[[Имя]]"` в кавычках;
- `tags` дублирует `type` одним значением.

### lexeme

```yaml
---
type: lexeme
lemma: gaśi          # латиница; совпадает с именем файла
cyrillic: гащи
pos: nouns           # verbs | nouns | adjectives | adverbs | pronouns | numerals
meaning: place
verb_type:           # 1 | 2 | irregular — только для pos: verbs
noun_class:          # "[[Class 7]]" — только для pos: nouns
root:                # "[[-gaśi-]]" или ["[[-seșe-]]", "[[-gaśi-]]"] у составных
phon:                # /.../
etym:
examples:
status: ok           # ok | unverified
tags: [lexeme]
---
```

Поля `script` больше нет: его первый элемент повторял `lemma`, а вложенность мешает Bases.

`root` — либо одна ссылка, либо список ссылок. Составных лексем сейчас три
(`seșegaśixxi`, `šasiše`, `šaxe`), и у каждой два корня; сводить их к одному значит
терять состав слова. Элементы списка обязаны быть в кавычках — `["[[-seșe-]]", "[[-gaśi-]]"]`,
а не `[[[-seșe-]], [[-gaśi-]]]`: без кавычек это невалидный YAML, и разбор ссылок ломается.

### root

```yaml
---
type: root
meaning: movement, placement
tags: [root]
---
```

### affix

```yaml
---
type: affix
cyrillic: га
meaning: "[[Class 5]]"
etym:
examples:
tags: [affix]
---
```

### noun_class

```yaml
---
type: noun_class
class: 1
prefix: "[[se-]]"
semantics: serpents, long objects
tags: [noun_class]
---
```

### verb_class

```yaml
---
type: verb_class
affix: -ss-
semantics: action
tags: [verb_class]
---
```

## Транслитерация

В `phonology.yaml` пять вариантов записаны как пять параллельных алфавитов по 18
позиций, выровненных по индексу; выравнивание и есть данные. Текущая заметка
`Transliteration.md` выкладывает их пятью отдельными JSON-списками и это соответствие
теряет. Заменяется одной таблицей, где строка — фонема, колонка — вариант:

| IPA | latin-1 | latin-2 | latin-3 | cyr-1 | cyr-2 |
| --- | ------- | ------- | ------- | ----- | ----- |
| θ   | t       | th      | t       | т     | ф     |
| s   | s       | s       | s       | с     | с     |
| sʲ  | c       | c       | c       | сь    | сј    |
| ʃ   | ș       | sh      | w       | ш     | ш     |
| ʂ   | š       | rz      | r       | ж     | ж     |
| ɕ   | ś       | ch      | z       | щ     | шј    |
| ç   | j       | j       | j       | хь    | ј     |
| x   | x       | x       | x       | х     | х     |
| χ   | g       | g       | g       | г     | г     |
| ħ   | q       | q       | q       | к     | к     |
| h   | h       | h       | h       | ь     | кј    |
| ɬ   | l       | l       | l       | л     | л     |
| 𝼆   | ļ       | lh      | y       | ль    | лј    |
| i   | i       | i       | i       | и     | и     |
| e   | e       | e       | e       | э     | е     |
| a   | a       | a       | a       | а     | а     |
| u   | u       | u       | u       | у     | у     |
| ʔ   | ’       | ’       | ’       | ъ     | ’     |

Правила поверх таблицы (текстом в той же заметке, они не табличные):

- геминированные согласные и долгие гласные — удвоением буквы: θː → `tt`/`tth`, ʂː → `šš`/`rrz`, iː → `ii`;
- двойные гласные — через гортанную смычку последним символом: aʔa → `a’a`;
- существует также вариант кириллицы по фонетическим правилам русского
  (`сэхишэ`/`сьэхьищэ` → `сэхышэ`/`сехище`) — пока не формализован.

Комментарии из `phonology.yaml`, которые надо перенести в `Inventory.md`:

- `u` — редкая гласная, встречается в заимствованиях;
- двойные гласные используются преимущественно грамматически (например, множественное число);
- мягкие согласные сочетаются с передними гласными, твёрдые — с задними;
- категории: soft `θ, sʲ, ɕ, ç, h, 𝼆`, hard `s, ʃ, ʂ, x, χ, ħ, ɬ`;
  front `i, e, a, ə`, back `ɨ, ɛ, ɑ, ɯ`.

## Имена файлов

Имя файла = лемма, символ в символ. Запрещены `? * : / \ | " < >` — они ломают ссылки
и не переносятся на Windows и в веб.

- `ļicejeśe?.md` → `ļicejeśe.md`, `status: unverified`
- `ļicexese?.md` → `ļicexese.md`, `status: unverified`
- `Future tense*.md` → `Future tense.md`, звёздочка означала «тенса нет, есть
  конструкция» — это уже сказано в тексте заметки
- `Past tense*.md` → `Past tense.md`

## Скрипты

**Только стандартная библиотека Python.** В окружении нет ни `pyyaml`, ни `pytest`, и
заводить venv ради двух скриптов — это ровно та хрупкость, от которой уходим. Поэтому
frontmatter разбирается собственным маленьким ридером (`tools/notes.py`), тесты — на
`unittest`, а `build/` пишет **JSON, а не YAML**: генерировать YAML без библиотеки
значит вручную возиться с кавычками и юникодом, то есть закладывать баг. Единственный
потребитель YAML — легаси-`dictionary.html`, который всё равно переписывается.

**`tools/build.py`** — читает заметки, пишет `build/`:

- `build/lexicon.json` — из frontmatter `Language/Lexicon/*.md`. Схема повторяет
  frontmatter один в один (`lemma`, `cyrillic`, `pos`, `meaning`, `verb_type`,
  `noun_class`, `root`, `status`), плоским списком, без группировки по частям речи:
  фильтровать по `pos` умеет любой потребитель. Ссылки `[[Class 7]]` разворачиваются
  в `Class 7`.
- `build/phonology.json` — из таблицы в `Transliteration.md` и списков в `Inventory.md`.
  Ключ `transliteration` — список записей `{ipa, latin-1, latin-2, latin-3, cyr-1, cyr-2}`,
  то есть таблица построчно, без потери выравнивания.

Версия языка (сейчас `0.4`) хранится в одном месте — во frontmatter `README.md`:

```yaml
---
version: 0.4
---
```

`build.py` читает её оттуда и проставляет в оба файла. Сейчас `0.4` продублирована в
трёх YAML; после миграции — ровно одно место.

**`tools/check.py`** — валидатор. Различает ошибки и предупреждения: ненулевой код
выхода только на ошибках, иначе неполнота языка будет блокировать сборку.

Ошибки — структурная поломка:

- поле не из схемы, отсутствие обязательного поля, `""` или `[]` вместо пустого;
- битая ссылка `[[...]]`;
- дубль `lemma`;
- имя файла не совпадает с `lemma`;
- символ `ş` (U+015F) вместо `ș` (U+0219) в любом файле;
- запрещённый символ в имени файла;
- в таблице транслитерации число строк не равно числу фонем в `Inventory.md`, или
  есть пустая клетка.

Предупреждения — неполнота, это нормальное состояние живого языка:

- лексема с `pos: nouns` без `noun_class`;
- лексема с `pos: verbs` без `verb_type`;
- лексема без `root`;
- корень, на который не ссылается ни одна лексема;
- `status: unverified`.

Предупреждения печатаются сводкой в конце — это рабочий список «что достроить».

Рабочая команда:

```bash
python tools/check.py && python tools/build.py
```

- корневой `phonology.yaml` — становится генерируемым `build/phonology.yaml`; его
  комментарии переносятся в `Inventory.md` (список выше) **до** удаления;
- `Untitled.base`, `Untitled 1–5.base` — пустые;
- `Untitled.canvas` — пустой;
- `2026-07-25.md` — пустая заметка;
- `input_words.txt`, `transliterations.txt`, `output_transliterations.txt`,
  `transposition/input.txt`, `transposition/output.txt` — вход и выход прогонов
  легаси-скриптов, не данные языка;

## Git

Волт сейчас untracked — он не в истории, бэкапа нет. Первый шаг миграции: закоммитить
его как есть, до перемещений, чтобы всё дальнейшее ложилось поверх зафиксированного
состояния. Перемещения — через `git mv`, чтобы история корневых файлов не оборвалась.

`.gitignore` дополняется:

```
.DS_Store
.obsidian/workspace.json
build/
```

`build/` не коммитится: сейчас его никто не потребляет (единственный потребитель —
легаси-`dictionary.html`), а закоммиченный генерируемый файл — это ровно тот второй
источник правды, от которого мы уходим. Когда появится потребитель, которому нужен
YAML из репозитория, решение пересматривается.
